How can Firewire audio interfaces be used today?

It is not impossible to use old Firewire audio interfaces today. To verify this, one only needs to turn on a desktop PC from a few years ago with an available Firewire port, Windows XP, and the corresponding driver installed to record or play back on an old version of Pro Tools. However, this is not practical. Windows XP, 7, and 8 have been obsolete for a long time, as have various versions of OS X. Obtaining drivers can be very difficult if the manufacturer does not publish them on their website. The same applies to old software such as old versions of Pro Tools. Additionally, there is the exposure to security threats we may face when downloading software from untrusted sources.

Each Firewire audio interface has different behaviors and characteristics. Not all are compatible with the same PCI-Firewire cards, nor do all have drivers for the same operating system versions. However, there are some methods that can be explored to use the interfaces on current hardware, which may in fact be necessary if attempting to reverse engineer that interface, whether to add support for it in fuegocable or for any other reason.

Desktop PC + PCI-Firewire + Windows/Hackintosh​

This method was already mentioned before and consists of building a desktop PC with a PCI-Firewire card inside and installing the necessary operating system and drivers. The main drawback of this option, of course, is portability because is not so easy to use it on the go. However this could work and it is also possible to find some Firewire audio interface that still has drivers available for current operating systems, although this is not for the majority.

USB–ADAT Interfaces​

Many of those Firewire audio interfaces may also offer ADAT ports. Some of them allow being used in standalone mode and in those limited cases where it is not necessary to use a host PC to configure the interface, USB-ADAT adapters can be used such as the RME Digiface USB.

It may also happen that some audio interfaces only need to be configured in standalone mode and require a host PC with an old operating system only once. After the configuration is done, they can be used via ADAT without needing to use an old PC again.

Thunderbolt Adapters​

Also mentioned previously, this is perhaps the most common alternative in the scene and discussed on internet forums. It consists of using certain Thunderbolt-Firewire and/or Firewire-Firewire adapters to connect audio interfaces to Apple computers such as MacBooks and Mac Minis. In this case, it is also necessary that the manufacturer has drivers/control software available for current versions of OS X.

Laptop PCIe Riser​

Another possible alternative is to use risers and MiniPCIe to PCI converters to connect a PCI-Firewire card through the MiniPCIe port that laptops usually have occupied by WiFi/Bluetooth cards. This option could theoretically work but portability is questionable because it is necessary to externally bring out certain PCI port signals outside the laptop chassis, in addition to the fact that risers usually require external power supplies. In this option, it is also necessary to have a driver/control software available for the operating system version running on the laptop.

Host Middleware (Embedded Linux FireWire-to-UAC)​

This alternative is more theoretical than practical, since the idea itself is not very promising but it is worth mentioning. There are various ways to use a Firewire port with Single-Board-Computers such as the Raspberry Pi 5 which has a PCI port that could perhaps be used with a riser as if it were a laptop, or by using a module such as the not-so-old Firehat which provides a Firewire port for devices like Raspberry Pi 5 or Radxa ROCK 2F. Since these are devices with ARM architecture, it is futile to think of any method to execute official Windows or Mac drivers, but there are Linux driver projects such as those already included in ALSA, so in theory it could be sufficient to connect some audio interfaces to the SBC (mainly those based on DICE and BridgeCo chips). In this way, one could also make use of the USB Gadget feature of the Linux kernel and thus develop a kind of Firewire-USB bridge.

However (and there are many caveats), it must be mentioned that ALSA drivers for Firewire interfaces do not have the same stability that other drivers such as USB have. This is because when it was common to use Firewire audio interfaces, Linux was not yet as established as an operating system for desktop systems as it is now, so development was not as intense as for current hardware.

In addition, even though there are examples of commercial products that make use of Linux USB Gadget to transfer audio such as AKAI MPC or Headrush pedalboards, those products usually function as stereo audio interfaces and not multi-channel, so it is also not a very promising option for audio interfaces with 4 or 8 channels in/out.

Again, this is not a good alternative but it is necessary to mention it to know it and understand if something of this idea can be proposed in another way in the future, or if it becomes inspiring for someone who brings a similar solution.
